# Snake Arena

Snake Arena — курсовой проект веб-приложения для соревнований алгоритмов,
управляющих змейками. По замыслу проекта команды пишут код прямо в браузере
и отправляют алгоритмы на матчи: змейки автономно перемещаются по общему полю,
собирают еду и избегают столкновений. Приложение должно выполнять алгоритмы
в изолированной среде, показывать ход соревнования в реальном времени
и определять победителя по правилам матча.

# Стек

React, TypeScript, Vite. Общие инструменты: Node.js, npm, ESLint и Git.

Настройки сборки — vite.config.ts, типов — tsconfig*.json, линтера — eslint.config.js.

Настройки Codex — .codex/config.toml, агент ревьюера — .codex/agents/reviewer.toml.

## Основные команды

- `npm ci` — установка зависимостей по lock-файлу.
- `npm run dev` — запуск Vite с автоматическим обновлением.
- `npm run build` — проверка TypeScript (`tsc -b`) и сборка в dist/.
- `npm run preview` — просмотр готовой сборки; после изменений нужна повторная сборка.
- `npm run lint` — ESLint.

Перед завершением изменений кода выполнять `npm run lint` и `npm run build`.

## Обязательные ограничения

- Различать предварительное ТЗ и фактическую реализацию в src/.
- По ТЗ пользовательский код должен выполняться в изолированной среде отдельно
  от основного веб-сервера.
- Перед завершением изменений кода выполнять проверки из раздела «Основные команды».
- При изменении команд, архитектурных правил или пользовательского поведения обновлять README.md, docs/ в том же
  изменении.

## Git

- По просьбе пользователя закоммитить изменения поручать создание коммита
  отдельному агенту модели `gpt-6.1-terra` с уровнем рассуждений `medium`.
- Коммитить и отправлять изменения только по запросу пользователя.
- Сообщения коммитов — на русском. Формат: `type(scope): описание`.
  Тип и скоуп — на английском; описание начинается с инфинитива с маленькой
  буквы: `feat(ai-agent): создать агента-ревьюера`.
  Заголовок ≤ 72 символов, без точки в конце.
- Разбивать весь набор изменений на логически самостоятельные части и при
  необходимости создавать несколько коммитов, даже по просьбе «закоммитить всё».
  Один коммит — одно логическое изменение. `fix` допустим как тип коммита.
  При необходимости тело объясняет причину, строки ≈ 72 символа.
- Не коммитить секреты и локальное окружение. Новые переменные документировать в README.md.
- Каждый коммит должен проходить обязательные проверки; хуки не обходить.
