# Текущее состояние Snake Arena

## Назначение и реализация

Реализован светлый главный экран: анимированная декоративная арена слева
и меню справа — создание матча, матчи, команды и правила.
Вошедшая команда может создать матч и открыть список матчей. Гостям доступен
пункт «Правила», защищённые пункты предлагают регистрацию или вход. Декоративное
поле на главной странице служит иллюстрацией.
Используется Tailwind CSS через Vite; токены и правила — в [design.md](design.md).
Главный экран упрощён: убраны мелкие декоративные подписи и футер,
увеличена типографика меню; движение непрерывное, плавное и относительно быстрое.
Для reduced-motion декоративное движение и переходы отключены.
Реализованы FastAPI, SQLite с SQLModel, регистрация и вход с серверной сессией. Общий движок обслуживает онлайн-матчи и тренировочные прогоны.
Точка входа `backend.main:app` экспортируется при импорте и проверяется backend-тестом.
Проверка кода, тренировки и новые онлайн-матчи используют один контейнер Python с отдельным seccomp-ограниченным процессом на вызов.

## Инструменты

Зависимости backend управляются через uv и `backend/pyproject.toml`, версии зафиксированы в `backend/uv.lock`. Для backend настроены тесты pytest; форматирование и его проверка настроены через Ruff. Для frontend используется Prettier.

## Регистрация и вход

Одна учётная запись соответствует одной команде. Регистрация принимает username,
отображаемое название из русских или английских букв, цифр, пробелов и `_` и пароль;
вход выполняется по username и паролю. Под полями входа отображаются только ошибки. Выход требует подтверждения в модальном окне.
Данные и серверные сессии сохраняются в SQLite в `data/`. Для гостей доступны
главный экран и правила, остальные пункты показывают предложение войти.

Лимит входа и регистрации разделяется по IP клиентов Vite через доверенный
локальный прокси; подмена служебного заголовка внешним клиентом не учитывается.

## Матчи в локальной сети

Организатор создаёт открытое лобби на 2–4 команды и выбирает размер поля. Участие
организатора в роли игрока занимает место. В списке видны вместимость и число
занятых мест. Одна команда может быть только в одном открытом матче в любой роли.
Участник может явно освободить место, пока лобби открыто.

Лобби показывает размер поля и состав, даёт открыть правила и документацию.
Набрав минимум две команды, организатор запускает подготовку на 1–120 минут.
Состав и дедлайн сохраняются. При остановке подготовки лобби открывается,
а отправленные версии и выбор остаются доступны при повторном запуске.

Во время подготовки участники видят редактор и проверяют `decide(state, memory)`.
В списке версий отображаются имя, время отправки до минуты и явный выбор.
По дедлайну сервер фиксирует выбранную версию или последнюю отправку.
Команды без отправок пропускают матч. Если допущено меньше двух команд,
матч завершается без победителя. Итог доступен организатору и всем командам
из состава подготовки.

Тренировочный матч открывается рядом с редактором. Доступны прямоугольное
поле, размеры, состав ботов, лимит тактов, количества объектов, генерация
и очистка. Карты можно сохранять и загружать. Тренировка позволяет
поставить прогон на паузу, выполнить такт, изменить скорость и
перезапустить матч на той же карте с текущим текстом.

Новые онлайн-матчи применяют все игровые механики из спецификации.
Состояние, память и выбор версий сохраняются в SQLite, состояние и итоги
транслируются через WebSocket. После перезапуска сервер продолжает
подготовку или раунд с последнего сохранённого состояния. Ранее
сохранённые раунды продолжаются в прежнем формате.
