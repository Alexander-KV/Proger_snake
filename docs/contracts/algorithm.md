# Контракт Python-алгоритма

Напишите функцию `decide(state, memory)` в редакторе лобби. Змейка вызывает
её перед каждым тактом, включая водный полушаг.

```python
def decide(state, memory):
    calls = (memory or {}).get("calls", 0)
    return {
        "direction": state["self"]["direction"],
        "memory": {"calls": calls + 1},
    }
```

## Наблюдение

Координаты `[x, y]` отсчитываются от левого верхнего угла с нуля. Ось `x`
направлена вправо, ось `y` вниз.

| Ключ `state` | Значение |
| --- | --- |
| `width`, `height` | Число столбцов и строк |
| `tick`, `ticks_remaining` | Номер такта с нуля и число оставшихся тактов, включая предстоящий |
| `self` | Снимок своей змейки, включая `allowed_directions` |
| `opponents` | Список снимков живых соперников |
| `obstacles`, `water`, `poison` | Списки координат препятствий, воды и яда |
| `food` | Объекты с `cell` и `kind` (`normal` или `gold`) |
| `powerups` | Объекты с `cell`, `kind: "shield"`, `duration: 10`, `blocks_poison: 1`, `blocks_water_slowdown: True` |

У змейки есть `id`, `name`, `head`, `body`, `length`, `direction`,
`score`, `alive`, `effects` и `movement`. Массив `body` перечисляет
занятые сеточные клетки от головы к хвосту. Поле `effects["shield_ticks"]`
показывает число тактов действия щита. Ноль означает отсутствие щита.

Снимок движения в середине водного шага вправо выглядит так.

```python
snake["head"] == [4.5, 3]
snake["movement"] == {
    "origin": [4, 3],
    "target": [5, 3],
    "progress": 0.5,
    "in_water": True,
    "slowed": True,
    "can_turn": False,
}
snake["allowed_directions"] == ["RIGHT"]  # Только в state["self"].
```

Когда голова находится в целой клетке, `origin` совпадает с `head`,
`target` равен `None`, а `progress` равен 0. `in_water` относится
к текущей клетке или к цели начатого водного шага. Войти в водную клетку
без щита можно за два такта, выйти на сухую — за один. На первом
полушаге клетки тела включая хвост сохраняются. `allowed_directions`
учитывает разворот на 180 градусов и блокировку поворота в воде. Риск
столкновения и объекты на целевой клетке оценивает сам алгоритм.

## Решение и память

`direction` принимает одно из значений `UP`, `DOWN`, `LEFT`, `RIGHT`.
Выбранное направление должно входить в `state["self"]["allowed_directions"]`.

`memory` получает `None` на первом такте. На каждом последующем такте
передаётся последнее принятое значение памяти этой змейки. Допустимы
словари со строковыми ключами, списки, строки, числа конечной величины,
логические значения и `None`. Максимум — 16 КиБ в UTF-8 после сериализации
и 64 уровня вложенности. При перезапуске память обнуляется. Исходник
загружается заново на каждом решении.

## Проверка и ограничения

- Максимальный размер исходника — 8000 байт в UTF-8.
- Лимит исполнения исходника и решения — 100 мс после запуска и изоляции
  одноразового процесса. Воркеры имеют лимиты по памяти и процессорному времени.
- Для алгоритмов доступны стандартные модули `collections`, `functools`,
  `heapq`, `itertools`, `math`, `operator` и `random`.
- Проверка вызывает функцию на контрольном снимке. Редактор показывает
  ошибки и позволяет перейти к строке, если она определена.
- Ошибка алгоритма на такте сохраняет предыдущее направление и память.
  При недоступности исполнителя такт не применяется.
