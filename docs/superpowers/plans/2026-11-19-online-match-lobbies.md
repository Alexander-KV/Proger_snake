# План реализации онлайн-матчей и лобби

> При реализации по задачам использовать `superpowers:executing-plans` или
> `superpowers:subagent-driven-development`. Выполненные шаги отмечать в списке.

**Цель** — дать командам в одной локальной сети создать матч, присоединиться и дождаться запуска в общем лобби.

**Архитектура** — FastAPI хранит матчи и участие в SQLite. React использует текущую сессию и одно соединение WebSocket на вкладку для подписки на состояние и отправки команд. Сервер публикует снимки после изменений. На втором этапе то же соединение передаёт игровые действия, ход раунда и результаты.

**Стек** — React, TypeScript, Vite, Tailwind CSS, FastAPI, SQLModel, SQLite и pytest.

**Спецификация** — [онлайн-матчи](../specs/2026-11-19-online-matches-design.md).

## Ограничения

- Первый этап включает форму создания, список матчей, лобби, статичное тренировочное поле, чтение правил и документации, выход участника и закрытие лобби организатором. Панель запуска, отсчёт, игровой раунд и редактор относятся к последующим этапам.
- Матч рассчитан на 2, 3 или 4 команды, по умолчанию 2. Квадратное поле имеет сторону 16, 24 или 32 клетки, по умолчанию 24. Начальная роль — «Организатор-наблюдатель». Организатор в роли игрока занимает место.
- Одна команда может находиться только в одном незавершённом матче в любой роли. Новые команды допускаются только до запуска и при свободном месте. До запуска участник может выйти и сразу освободить место.
- Первая версия принимается в локальной сети. Защищённые экраны используют действующую сессию. Список, состав и действия передаются по WebSocket. Периодического опроса нет. Идентификаторы в коде на английском, интерфейс и документация на русском.
- Коммиты создавать при отдельном запросе пользователя. Перед каждым коммитом выполнять форматирование и обязательные проверки по `AGENTS.md`.

## Особые случаи для проверки

- Потерян ответ сервера на создание. Повтор с тем же ключом возвращает исходный ID.
- Две вкладки одной команды подключаются в разные лобби. Создаётся ровно одно участие.
- Две команды претендуют на последнее место. Обновлённый счётчик не превышает вместимость.
- Организатор закрывает лобби, пока другая команда присоединяется. Закрытый матч освобождает все связи независимо от порядка запросов.
- Участник открывает правила, теряет связь или сессию. Его место сохраняется, экран восстанавливается после обновления данных или входа.

### Контракт WebSocket первого этапа

Соединение открывается по `/api/ws` на адресе сайта. Одно соединение на вкладку
обслуживает одну активную подписку. При переключении экрана клиент отправляет
новую подписку. Подписку можно снять командой `unsubscribe`. Команды и подписки
передаются JSON-сообщениями вида `{type, request_id, payload}`. Сервер отвечает
на команду сообщением `{type: "result", request_id, payload}` или
`{type: "error", request_id, code, message}`. Для `active_match` в ошибке
передаётся также `match_id`.

| Клиентское сообщение | Данные и результат |
| --- | --- |
| `subscribe` | `{view: "list"}` или `{view: "lobby", match_id: number}`. После подтверждения сервер отправляет `snapshot` с `subscription_id`, равным `request_id` подписки. |
| `unsubscribe` | Пустые данные, подтверждение `result`. |
| `create_match` | `{capacity, board_size, organizer_role}`. Ответ `{id}`. Повтор с тем же `request_id` возвращает исходный ID. |
| `join_match` | `{match_id}`. Ответ `{id}` для нового и существующего участия в этом матче. |
| `leave_match` | `{match_id}`. Повтор для покинутого лобби сохраняет участие в другом матче. |
| `close_match` | `{match_id}`. Повтор для того же организатора безопасен. |

Пакет `snapshot` содержит `type`, `subscription_id` и `payload` со списком
`MatchList` или деталями `MatchLobby`. `MatchList` содержит
`current_match_id: number | null` и `matches: MatchSummary[]`.
`MatchSummary` содержит `id`, `capacity`, `board_size`, `participant_count`,
`status`. `MatchLobby` расширяет сводку полями `organizer: TeamLabel`,
`participants: TeamLabel[]` и `my_role: MatchRole`. `TeamLabel` содержит `id` и
`name`. `MatchRole` соответствует роли в таблице участия.

Коды ошибок — `match_not_found`, `forbidden`, `match_closed`, `active_match`,
`match_full`, `match_not_waiting`, `request_id_reused`, `invalid_request`,
`unavailable`.
После закрытия лобби либо утраты доступа сервер отправляет `subscription_end`
с `subscription_id` и причиной. Ключ `request_id` состоит из 32
шестнадцатеричных символов. При завершении сессии сервер закрывает
соединение с кодом `1008`.
