# Snake Arena

**Snake Arena** — учебное веб-приложение для соревнования алгоритмов, управляющих змейками. Команда разрабатывает стратегию: получает наблюдение об игровом поле и возвращает направление движения. Несколько независимых алгоритмов соревнуются по общим правилам, а зрители наблюдают за матчем и результатами.

> **Текущее состояние.** Работают главная страница, учётные записи команд и первый этап онлайн-матчей в локальной сети. См. [спецификацию матчей](docs/superpowers/specs/2026-11-19-online-matches-design.md) и [текущее состояние](docs/current-state.md).

## Идея и сценарий

Ценность проекта — **соревнование стратегий**, а не ручное управление змейками.

1. Организатор создаёт матч и задаёт параметры соревнования.
2. Каждой участвующей змейке назначается алгоритм.
3. На каждом игровом тике алгоритмы получают сведения о текущем состоянии поля и выбирают направление.
4. Движок одновременно применяет решения, рассчитывает еду, столкновения, очки и выбывание.
5. Зрители следят за игрой; по окончании раунда отображаются результаты.

Для базовой ноябрьской версии предусмотрены заранее подготовленные алгоритмы. В последующих версиях участники смогут писать и проверять собственные стратегии на сайте.

## Что уже реализовано

- Главная страница Snake Arena с анимацией и навигацией.
- Регистрация команды (учётная запись = одна команда), вход, выход с подтверждением и проверка сессии.
- Подсказки под полями регистрации, обработка ошибок форм и ограничение доступа к защищённым разделам для гостя.
- Frontend-проект на **React, TypeScript, Vite и Tailwind CSS**.
- Backend на **Python, FastAPI, SQLModel и SQLite**.
- Локальная связка Vite `/api` → FastAPI, инструменты форматирования и базовые проверки.
- Создание матча, список и общее лобби через WebSocket. Организатор выбирает размер поля, число команд и режим участия. Команда занимает место только в одном открытом матче. В лобби доступны статичное тренировочное поле, правила и документация. Участник может выйти, организатор может закрыть лобби.

**Следующие этапы** — запуск и трансляция игрового раунда, редактор и изолированное исполнение алгоритмов, тренировочный режим и повторы.

## Ближайший этап — демонстрационный MVP (до 23 ноября 2026)

Планируется получить работающий сценарий:
- матч с **2–4 змейками** и **2–3 подготовленными стратегиями**;
- один общий игровой цикл с одновременными тиками;
- столкновения, еда, рост, очки, выбывание и итог раунда;
- создание и запуск матча через существующий сайт;
- живое отображение поля и итоговая таблица;
- проверка основного сценария вручную и исправление критических ошибок.

**Не входит в обязательный ноябрьский MVP:** загрузка и исполнение произвольного кода участников, поддержка множества языков, полноценный редактор кода, обученная нейросеть, турниры и сложная система бонусов.

### Единый интерфейс управления

Система проектируется вокруг контракта **Observation → Direction**: для каждой змейки формируется игровое наблюдение, а стратегия возвращает одно из направлений: `UP`, `DOWN`, `LEFT`, `RIGHT`.

Все стратегии должны принимать решение на основе **одного и того же снимка игрового тика**. Если алгоритм не вернул допустимое новое направление за отведённое время, базовое правило — продолжить движение прямо. Подробный JSON-контракт и правила конфликтов фиксируются перед интеграцией в `docs/contracts/match.md` (после его создания).

Так можно заменить простой алгоритм с `if` более сложной эвристикой или ИИ-модулем, не переписывая игровую физику.

## Дальнейшее развитие (не считается готовым)

- Встроенный редактор с сохранением версий алгоритмов.
- Безопасный и изолированный запуск пользовательского кода как минимум одного выбранного языка.
- Тренировочные матчи против стандартных стратегий.
- Повторы соревнований и анализ ошибок.
- Дополнительные объекты: препятствия, разные виды еды, бонусы и особые карты.
- ИИ-стратегия либо анализ сыгранных матчей.
- Турнирный режим и рейтинги.

Способ запуска кода, точные правила победы, доступная область видимости, количество команд и формат ИИ пока подлежат уточнению. **Проект не предназначен для публичного запуска недоверенного кода без отдельной защищённой среды исполнения.**

## Локальный запуск

Нужны **Node.js и npm**, **Python 3.11+** и [uv](https://docs.astral.sh/uv/).

Склонировать репозиторий:

```bash
git clone https://github.com/Alexander-KV/Proger_snake.git
cd Proger_snake
```

**Терминал 1 — backend (из корня репозитория):**

```bash
uv sync --project backend --locked
uv run --project backend --locked uvicorn backend.main:app --reload --host 127.0.0.1 --no-proxy-headers
```

**Терминал 2 — frontend (из корня репозитория):**

```bash
npm ci
npm run dev
```

Открыть адрес, который покажет Vite в терминале (обычно `http://localhost:5173`). Запросы к `/api` в режиме разработки перенаправляются в локальный FastAPI на `127.0.0.1:8000`. База SQLite создаётся в каталоге `data/` и не коммитится в Git.

### Матчи в локальной сети

Оставьте FastAPI на `127.0.0.1:8000`. В терминале frontend выполните следующую команду, подставив локальный IPv4-адрес компьютера с сервером:

```bash
npm run dev -- --host <LAN_IP> --strictPort
```

На каждом компьютере в той же сети откройте `http://<LAN_IP>:5173` и войдите под своей командой. Vite проксирует запросы учётной записи и WebSocket `/api/ws` на FastAPI. Для рассылки обновлений используется один процесс FastAPI.

**Важно:** текущая конфигурация авторизации и прокси рассчитана на локальный HTTP. Для публичного развёртывания нужны отдельные настройки HTTPS, доверенных прокси и безопасности сессий. Не публикуйте текущий dev-сервер в интернет.

## Проверки

```bash
npm run lint
npm run build
npm run format:check
uv run --project backend --locked python -m pytest backend/tests
uv run --project backend --locked ruff format --check backend
```

Разрабатываемый матч должен дополнительно проверяться вручную: создание раунда, алгоритмы, столкновения, очки, завершение, ошибки и запуск на чистом окружении.
