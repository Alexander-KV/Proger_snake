# Техническое задание проекта Snake Arena

**Тип проекта:** курсовая работа  
**Название:** Snake Arena  
**Формат:** веб-приложение  
**Команда разработки:** 4 человека (Project Manager, Backend Developer, Frontend Developer, QA Engineer)  
**Планируемый срок завершения:** 15 декабря 2026 года  
**Статус документа:** предварительное ТЗ, требования уточняются.

---

## 1. Описание проекта

**Snake Arena** — веб-приложение для проведения соревнований между алгоритмами, управляющими змейками.

Пользователи объединяются в команды, разрабатывают собственные алгоритмы управления змейкой на выбранном языке программирования и участвуют в соревнованиях.

Главная особенность приложения — возможность писать программный код непосредственно на сайте.

После запуска соревнования змейки автоматически перемещаются по общему игровому полю, собирают еду, увеличиваются в длине и пытаются избежать столкновений.

Победитель определяется на основании установленных правил соревнования.

## 2. Цель проекта

Разработать веб-приложение, позволяющее:

- Создавать соревнования между несколькими командами.
- Разрабатывать алгоритмы управления змейками непосредственно в браузере.
- Поддерживать несколько языков программирования.
- Автоматически выполнять алгоритмы участников.
- Визуализировать соревнование в реальном времени.
- Определять победителя и отображать результаты.
- Использовать элементы искусственного интеллекта.

## 3. Функциональные требования

### 3.1. Команды и участники

- Создание команды.
- Указание названия команды.
- Возможность участия нескольких человек в одной команде.
- Привязка алгоритма к команде.
- Участие нескольких команд в одном соревновании.

**Требует уточнения:** необходимость регистрации, авторизации, приглашений и разграничения прав участников.

### 3.2. Редактор программного кода

Веб-приложение должно предоставлять встроенный редактор кода.

Основной функционал:

- Выбор языка программирования.
- Написание и редактирование алгоритма.
- Подсветка синтаксиса.
- Сохранение написанного кода.
- Отображение ошибок компиляции или выполнения.
- Отправка алгоритма для участия в соревновании.

Дополнительно рассматривается возможность тестового запуска алгоритма до соревнования.

**Предварительно рассматриваемые языки:** Python, JavaScript, C++.

Окончательный список поддерживаемых языков необходимо согласовать.

### 3.3. Игровое поле

- Прямоугольное поле, разделённое на клетки.
- Одновременное размещение нескольких змеек.
- Каждая змейка принадлежит отдельной команде.
- У каждой змейки собственный цвет.
- На поле появляются объекты еды.
- Размер поля определяется настройками соревнования.
- Все змейки перемещаются автоматически.

### 3.4. Игровая механика

- Каждая змейка управляется алгоритмом своей команды.
- Алгоритм определяет направление следующего движения.
- Все змейки совершают действия в рамках общего игрового цикла.
- При поедании еды змейка получает очки и увеличивается в длине.
- При столкновении с препятствием, собственным телом или другой змейкой происходит выбывание.
- Выбывшая змейка больше не участвует в матче.
- Игра завершается при выполнении условия окончания соревнования.

**Предварительные правила победы:**

1. Если осталась одна змейка, она объявляется победителем.
2. Если достигнут лимит ходов, победитель определяется по количеству очков.
3. При равенстве очков может учитываться длина змейки.

Точные правила столкновений, начисления очков и завершения игры подлежат согласованию.

### 3.5. Управление соревнованием

- Создание матча.
- Выбор количества участвующих команд.
- Настройка параметров игрового поля.
- Подключение алгоритмов команд к соревнованию.
- Проверка готовности участников.
- Запуск матча.
- Автоматическое завершение матча.
- Отображение победителя и итоговых результатов.

### 3.6. Визуализация

Интерфейс должен обеспечивать:

- Отображение игрового поля.
- Визуализацию движения змеек.
- Отображение еды.
- Отображение названий команд.
- Отображение количества очков.
- Отображение состояния участников.
- Отображение результатов завершённого матча.

Данные игрового поля должны обновляться автоматически без перезагрузки страницы.

### 3.7. Выполнение алгоритмов

Система должна обеспечивать:

- Приём программного кода участников.
- Определение выбранного языка программирования.
- Запуск алгоритмов в изолированной среде.
- Передачу алгоритмам информации о текущем состоянии игры.
- Получение направления движения от каждого алгоритма.
- Ограничение времени выполнения.
- Обработку ошибок и некорректных ответов.
- Предотвращение влияния ошибок одного алгоритма на остальные.

Пользовательский код не должен выполняться непосредственно в процессе основного веб-сервера.

### 3.8. Искусственный интеллект

В приложении необходимо предусмотреть интеграцию ИИ.

Возможные варианты:

- Интеллектуальная змейка-соперник.
- Анализ алгоритмов участников.
- Рекомендации по улучшению стратегии.
- Анализ результатов соревнования.

**Конкретный вариант интеграции ИИ уточняется с преподавателем.**

## 4. Предварительная архитектура

Приложение разделяется на следующие компоненты:

| Компонент | Назначение |
|---|---|
| Frontend | Пользовательский интерфейс |
| Code Editor | Написание алгоритмов |
| Backend API | Управление командами и соревнованиями |
| Game Engine | Игровая логика |
| Code Runner | Выполнение алгоритмов |
| Sandbox | Изоляция пользовательского кода |
| Database | Хранение информации |
| WebSocket | Обновление игрового поля |

### Предварительный технологический стек

- **Frontend:** React / Next.js.
- **Backend:** Python / FastAPI.
- **Database:** PostgreSQL.
- **Обмен данными:** REST API, WebSocket.
- **Редактор кода:** Monaco Editor.
- **Контейнеризация:** Docker.

Указанные технологии являются предварительным предложением, а не окончательным требованием.

- Корректная обработка игровых событий.
- Стабильная работа нескольких алгоритмов одновременно.
- Обработка ошибок пользовательского кода.
- Изоляция выполнения алгоритмов.
- Разделение интерфейса, игровой логики и системы выполнения кода.
- Возможность расширения списка поддерживаемых языков.
- Возможность добавления новых игровых механик.
- Наличие автоматизированных тестов.
- Документированный порядок запуска приложения.

## 7. Критерии готовности проекта

Курсовой проект считается функционально завершённым, если:

- Пользователь может написать алгоритм на сайте.
- Алгоритм может быть проверен и отправлен на соревнование.
- Приложение запускает алгоритмы поддерживаемых языков в изолированной среде.
- Несколько змеек участвуют в одном матче.
- Все основные игровые механики работают корректно.
- Соревнование отображается в браузере.
- Победитель определяется автоматически.
- Ошибки одного алгоритма не приводят к остановке всего приложения.
- Реализована согласованная функция ИИ.
- Основные сценарии проверены тестами.
