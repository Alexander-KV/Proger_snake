# Snake Arena

**Snake Arena** — учебное веб-приложение для соревнования алгоритмов, управляющих змейками. Команда разрабатывает стратегию: получает наблюдение об игровом поле и возвращает направление движения. Несколько независимых алгоритмов соревнуются по общим правилам, а зрители наблюдают за матчем и результатами.

> **Текущее состояние.** Работают лобби, подготовка алгоритмов, тестовые прогоны и онлайн-матчи в локальной сети. См. [текущее состояние](docs/current-state.md).

## Идея и сценарий

Ценность проекта — **соревнование стратегий**, а не ручное управление змейками.

1. Организатор собирает участников в лобби и запускает подготовку, задав время в минутах.
2. Команды пишут и проверяют Python-алгоритмы. Пока таймер идёт, они могут запускать тренировку на отдельном настраиваемом поле против стандартных ботов.
3. Каждая отправка сохраняет исходник отдельной версией с именем «Версия #N» и временем отправки до минуты. Участник может переименовать версию и отдельной кнопкой выбрать её для игры.
4. По серверному дедлайну выбранные версии фиксируются и матч начинается автоматически. Без явного выбора используется последняя отправка. Команда без отправок пропускает раунд. Тренировка не влияет на таймер или выбор команды.
5. Алгоритмы получают состояние одного такта и возвращают решение. Движок применяет решения одновременно. Участники следят за полем, очками и итоговой таблицей.

Реализация описана в [текущем состоянии](docs/current-state.md), а детали правил — в [спецификации подготовки алгоритмов и онлайн-матчей](docs/superpowers/specs/2026-11-19-algorithm-matches-design.md).

## Что уже реализовано

- Главная страница Snake Arena с анимацией и навигацией.
- Регистрация команды (учётная запись = одна команда), вход, выход с подтверждением и проверка сессии.
- Подсказки под полями регистрации, обработка ошибок форм и ограничение доступа к защищённым разделам для гостя.
- Frontend-проект на **React, TypeScript, Vite и Tailwind CSS**.
- Backend на **Python, FastAPI, SQLModel и SQLite**.
- Локальная связка Vite `/api` → FastAPI, инструменты форматирования и базовые проверки.
- Создание матча, список и лобби через WebSocket. Организатор выбирает размер поля, число команд, роль и время на подготовку от 1 до 120 минут. Команда занимает место только в одном открытом матче. Правила и документация доступны в лобби.
- Подсветка Python, проверка кода, список отправленных версий, их переименование и независимый выбор для онлайн-матча.
- Тестовое поле с четырьмя стандартными ботами, сохранением карт и управлением воспроизведением.
- Автоматический запуск раунда на дедлайне, трансляция, очки и итоговая таблица.

## Алгоритмы и правила раунда

Python-алгоритм реализует `decide(state, memory)` и возвращает словарь с
`direction` (`UP`, `DOWN`, `LEFT`, `RIGHT`) и `memory`. На первом вызове
память может быть `None`. Память принадлежит конкретной змейке. Наблюдение
содержит состояние поля, змеек, доступных поворотов, движения и эффектов.
Весь пользовательский Python для проверки, тренировок и онлайн-матчей
исполняется в одном выделенном контейнере на проект с изоляцией вызовов
друг от друга. Проверка показывает синтаксические ошибки, ошибки контракта
и исполнения, включая таймаут. См. [контракт алгоритма](docs/contracts/algorithm.md).

В новых раундах действуют общие правила симуляции и онлайн-матча. Обычная
еда даёт 10 очков, золотая — 30, обе добавляют сегмент. Вода замедляет
движение до половины клетки за такт; на полушаге нельзя поворачивать.
Яд отнимает сегмент и убивает змейку длиной 2. Временный щит защищает
от одного яда и от замедления в воде. Столкновения со стеной, препятствием
или змейкой смертельны. При столкновении голов или обмене клетками голов
погибают обе. При проверке столкновений учитываются освобождаемые хвосты.
Единственный выживший побеждает сразу. По лимиту тактов сравниваются очки
выживших, возможна ничья. Если все погибли, победителя нет.

Тренировка поддерживает размеры поля, число змеек, лимит тактов, выбор
механик и количество объектов. Доступны генерация, очистка, перегенерация,
сохранение и повтор карты, выбор ботов, пауза, одиночный шаг, продолжение,
перезапуск, скорость и результаты. Подробности — в
[спецификации](docs/superpowers/specs/2026-11-19-algorithm-matches-design.md) и
[плане](docs/superpowers/plans/2026-11-19-algorithm-matches.md).

## Локальный запуск

Нужны **Node.js и npm**, **Python 3.11+**, [uv](https://docs.astral.sh/uv/) и Docker для запуска алгоритмов.

Склонировать репозиторий:

```bash
git clone https://github.com/Alexander-KV/Proger_snake.git
cd Proger_snake
```

### Контейнер Python

Если контейнер `snake-arena-runner` уже запущен, сохраните его токен в
`.env.local`. Команда не выводит значение на экран и сохраняет существующий
файл, если он уже есть.

```bash
(
  umask 077
  set -C
  runner_token="$(docker exec snake-arena-runner printenv SNAKE_RUNNER_TOKEN)" || exit 1
  test -n "$runner_token" || exit 1
  printf 'SNAKE_RUNNER_TOKEN=%s\n' "$runner_token" > .env.local
)
```

Если команда сообщила, что `.env.local` уже существует, откройте этот файл
и заполните в нём `SNAKE_RUNNER_TOKEN` значением из запущенного контейнера.
Токен можно получить через
`docker exec snake-arena-runner printenv SNAKE_RUNNER_TOKEN`.

При первом запуске вместо этого сгенерируйте токен в корне проекта.
Пример переменных находится в [`.env.local.example`](.env.local.example).

```bash
(
  umask 077
  set -C
  python3 -c 'import secrets; print("SNAKE_RUNNER_TOKEN=" + secrets.token_urlsafe(32))' > .env.local
)
```

Затем соберите образ и запустите один контейнер.

```bash
docker build -t snake-arena-runner backend/training
docker run --rm -d --name snake-arena-runner --read-only --init \
  --cap-drop ALL --security-opt no-new-privileges --memory 512m --pids-limit 32 \
  --cpus 4 -p 127.0.0.1:8765:8765 --env-file .env.local snake-arena-runner
```

FastAPI читает `SNAKE_RUNNER_TOKEN` и `SNAKE_RUNNER_PORT` из `.env.local`
в корне проекта при запуске. Заданные переменные окружения имеют приоритет.
При изменении файла перезапустите FastAPI. Держите токен в локальном
окружении и не добавляйте его в Git.
Остановить исполнитель можно командой `docker stop snake-arena-runner`.

**Терминал 1 — backend (из корня репозитория)**

```bash
uv sync --project backend --locked
uv run --project backend --locked uvicorn backend.main:app --reload --host 127.0.0.1 --no-proxy-headers
```

**Терминал 2 — frontend (из корня репозитория)**

```bash
npm ci
npm run dev
```

Открыть адрес, который покажет Vite в терминале (обычно `http://localhost:5173`). Запросы к `/api` в режиме разработки перенаправляются в локальный FastAPI на `127.0.0.1:8000`. База SQLite создаётся в каталоге `data/` и не коммитится в Git.

### Матчи в локальной сети

Оставьте FastAPI на `127.0.0.1:8000`. В терминале frontend выполните следующую команду, подставив локальный IPv4-адрес компьютера с сервером:

```bash
npm run dev -- --host <LAN_IP> --strictPort
```

На каждом компьютере в той же сети откройте `http://<LAN_IP>:5173` и войдите под своей командой. Vite проксирует запросы учётной записи и WebSocket `/api/ws` на FastAPI. Для рассылки обновлений используется один процесс FastAPI.

**Важно:** текущая конфигурация авторизации и прокси рассчитана на локальный HTTP. Для публичного развёртывания нужны отдельные настройки HTTPS, доверенных прокси и безопасности сессий. Не публикуйте текущий dev-сервер в интернет.

## Проверки

```bash
npm run lint
npm run build
npm run format:check
uv run --project backend --locked python -m pytest backend/tests
uv run --project backend --locked ruff format --check backend
```

С запущенным контейнером и заданным `SNAKE_RUNNER_TOKEN` pytest также проверяет реальное исполнение, изоляцию, память и таймауты. Приёмка в браузере покрывает подготовку, тренировку, выбор версий, онлайн-матч и результат.
